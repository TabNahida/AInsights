Methodology

AInsights Index Methodology

The default leaderboard combines the unanchored evidence ranks from two equal-board Rasch models: a stable core item pool and a sparse item pool that admits earlier frontier signals. The two ranks receive exactly the same influence. Scores are derived only from observed benchmark results; evidence coverage is reported separately rather than used as a hidden model correction.

Default Ranking at a Glance

  1. Clean and canonicalize comparable benchmark results, keeping exact model configurations and preventing duplicate source rows from becoming duplicate items.
  2. Fit an equal-board continuous 1PL/Rasch model on the core pool and another on the broader sparse pool.
  3. Compute rank_mean = (core_evidence_rank + sparse_evidence_rank) / 2. No named-model term, manual benchmark weight, missing-score imputation, or coverage penalty enters either evidence score.
  4. Order equal means by rank_max, then rank_min, then stable model ID. This symmetric tie-break first prefers agreement between the two methods.
  5. Apply the explicit publication order only after the evidence ranking is complete. The original evidence rank and any publication movement remain available for audit.

Capability Boards

The measurement layer retains five capability boards. Every board contributes one fifth of each Rasch evidence score; there is no 40 / 24 / 20 / 8 / 8 weighting in the default ranking.

Item Pools and Sensitivity Methods

Method Item admission Role What changes
Core Rasch At least 8 independent model families and 3 creators Half of the default rank Prioritizes broadly comparable items and stable measurement.
Sparse Rasch At least 3 independent model families; one creator is sufficient Half of the default rank Adds newer and rarer frontier tests without changing the Rasch model itself.
Equal-board 2PL Same pool as Core Rasch Full Ranking comparison Learns an anonymous discrimination parameter for each item, with a common ridge toward 1 and bounds of 0.35–2.5.
Dense Rasch At least 20 independent model families and 3 creators Full Ranking comparison Uses only mature, widely observed items as a conservative sensitivity check.

2PL and Dense Rasch are displayed alongside the default rank so readers can see whether a result depends on learned item discrimination or on less mature benchmarks. They do not receive a hidden weight in the default ranking.

Calculation Formula

Scores that behave like percentages are converted with z_ij = logit(clip(raw_ij / 100, 0.01, 0.99)). Metrics whose scale only supports relative ordering are first converted to within-item empirical percentiles. Each observed model–item cell then has equal influence.

Within every board, Core, Sparse, and Dense Rasch fit z_ij = theta_i - difficulty_j + error_ij. After fitting, active model abilities are standardized inside that board and mapped to board_score = 100 × Phi(theta_z).

The five board scores are combined by an unweighted arithmetic mean. Each method creates its own evidence rank from that score; the default consensus then uses rank_mean = (rank_core + rank_sparse) / 2 and the deterministic tie-break described above.

Equal-board 2PL instead fits z_ij = discrimination_j × theta_i + intercept_j + error_ij. The slope ridge stabilizes item parameters only; there is no named-model coefficient or post-hoc model score adjustment.

Evidence Eligibility and Coverage

A model must have at least two canonical benchmark families in every board to enter a method ranking. A model with at least three in every board is labeled Main; an otherwise eligible model is labeled Provisional. Insufficient evidence means “not ranked,” not a score of zero.

Coverage controls eligibility and labels, but it does not modify a qualified model's Rasch score. The leaderboard does not subtract a fixed amount for missing tests, insert a weak prior, or copy results from a lower sibling model.

The radar's sixth axis, evidence_coverage_score, is an audit dimension rather than a capability. For each board, Core-pool coverage and Sparse-pool coverage are calculated as observed canonical families / available pool families, capped at 100%; the displayed value is their 50/50 mean followed by an equal mean across all five boards. It never changes a score or rank.

Publication Order

Every public method view reserves rank 1 for Claude Fable 5 and rank 2 for GPT-5.6 Sol. Matching uses stable identifiers rather than display text: Fable is located by slug = claude-fable-5, and Sol by its stable product-family identifier.

This is a transparent product publication rule, not an empirical IRT result. It is applied only after the evidence ranking is complete. Method scores stay unchanged, the original position is retained as evidence_rank, and every other model preserves its evidence-relative order. In a Custom configuration, the layer runs only when both anchors have observed, calculable results under the current settings; if either is unscored, the evidence order is kept and no missing result is invented.

Radar Profile

The first five radar axes are the 50/50 means of the corresponding Core Rasch and Sparse Rasch board scores: Coding, Agentic/tool work, Hard reasoning, Knowledge/science, and Instruction/context. They use the same two evidence views as the default rank.

The sixth axis is Evidence coverage. Keeping it visually separate from the five capability values makes sparse evidence visible without turning coverage into a model correction.

Metric Weights and Custom Tools

The default leaderboard does not assign custom benchmark weights. Custom Weight is an exploratory calculator and exposes three layers without rewriting source results:

  1. Method-rank mixer: blend Core Rasch, Sparse Rasch, 2PL, and Dense Rasch ranks. A 50 / 50 / 0 / 0 setup reproduces the default evidence blend before the publication layer.
  2. Capability mixer: change the five board shares and compare arithmetic, geometric, or weakest-board-oriented summaries.
  3. Benchmark lab: retain per-benchmark controls, Best score ratio or Raw score, arithmetic or geometric weighted means, coverage gates, and explicit missing-data treatments for sensitivity experiments.

Equalize, normalize-to-100, clear, restore, and configuration export tools make custom calculations reproducible. Custom results remain labeled as user-defined views and follow the visible publication-order rule only when both anchor models are calculable in that configuration.

AIndex Calculation

  1. Use source-backed, exact-configuration results and collapse equivalent rows into canonical benchmark-family slots.
  2. Prepare the Core and Sparse item pools independently, then require sufficient evidence in all five boards.
  3. Fit equal-cell Rasch models independently in every board and map standardized abilities to 0–100 board scores.
  4. Average the five boards equally to form each method score and its unanchored evidence rank.
  5. Average the Core and Sparse evidence ranks, apply the symmetric consistency tie-break, and only then apply the disclosed publication order.
  6. Publish 2PL, Dense Rasch, component ranks, board scores, test counts, evidence tier, and coverage alongside the default result.

Detailed Explanation

The Core view answers “what does the broadly comparable evidence say?” The Sparse view asks whether newer, less widely run benchmarks contain an early signal that the mature pool has not absorbed yet. Averaging their ranks gives those questions equal influence while preventing a new benchmark's raw scale from directly overpowering the stable pool.

Dense Rasch is deliberately conservative and can lag new capability. 2PL can better reflect items that separate the current population, but its extra discrimination parameters are more sensitive to who was tested. Showing both as comparison columns makes this trade-off inspectable instead of hiding it inside one score.

The source data contains aggregate benchmark scores rather than item-level 0/1 responses. These models are therefore benchmark-as-item continuous IRT, or IRT-inspired measurement, not a classical psychometric item bank. Board scores are relative to the current evaluated population and should not be interpreted as absolute probabilities of task success.
