Methodology · Scheme 18

AInsights Index Methodology

AIndex Scheme 18 gives every capability board a direct 0–100 score. A small set of mandatory tests determines a geometric Core score; independently controlled extension tests can only raise that score when they provide positive evidence beyond an anonymous cohort-wide expectation. The final AIndex score is the equal arithmetic mean of the five board scores.

Default Ranking at a Glance

  1. Canonicalize source-backed, direct 0–100 results and select the default deduplicated model population before fitting.
  2. Require every mandatory Core result in each board, then calculate that board's unweighted geometric Core mean.
  3. For every eligible extension item, fit one anonymous OLS relationship from Core score to the observed extension result across the current cohort.
  4. Keep only positive residuals, combine them with a zero-neutral monotone log-sum-exp function, and cap the increment using the pooled positive-residual mean + sqrt(2) × SD.
  5. Calculate board_score = min(100, core_score + capped_bonus), then average the five board scores equally and sort the unrounded final score descending.

Every board contributes exactly one fifth of AIndex. There is no hidden board weighting and no later model-specific adjustment.

A canonical benchmark family occupies at most one Core slot within a board. A family may appear in more than one board when the same observed result supplies relevant evidence for multiple capabilities; this creates some cross-board correlation and is disclosed as a limitation.

Core Score

For a board with mandatory results x_1 ... x_k, Scheme 18 uses the unweighted geometric partial-credit score:

core_score = 100 × exp((1/k) × sum(log(clip(x_j / 100, 10^-6, 1))))

The formula stays on the native percentage scale. It has no canonical T transformation, fixed 50-point center, percentile conversion, item-specific weight, or named-model coefficient. A low mandatory result has more leverage than it would under an arithmetic mean, so broad Core mastery matters.

A model is not scored when a mandatory Core value is missing. Scheme 18 does not manufacture a Core value from a sibling model, prior, cohort mean, or lower-effort configuration.

Independent Extension Evidence

Extension items must be controlled by an organization that is not a ranked model vendor. Vendor-controlled benchmark families, including GDPval and BrowseComp, are excluded; ITBench remains excluded because its controller is also a ranked model vendor. Equivalent representations of one canonical family cannot create duplicate bonus opportunities inside a board.

The extension pool includes independently controlled public benchmarks with sufficient observed coverage. Some reported results still use mixed, vendor-reported, agent-scaffold, prompt, or version-sensitive protocols. Their benchmark ownership is independent, but that does not make every result protocol identical. Sources, operators, versions, and coverage remain visible so this limitation can be audited.

Extension evidence is only-add. Missing extension results remain absent, contribute no residual, receive no imputed zero or neutral score, and never reduce the mandatory Core.

Anonymous Positive Residuals

For each extension item j, the current deduplicated cohort supplies all observed pairs of board Core score c_i and extension result y_ij. Scheme 18 fits:

predicted_ij = clip(alpha_j + max(0, beta_j) × c_i, 0, 100)

positive_residual_ij = max(y_ij - predicted_ij, 0)

The OLS intercept and non-negative slope are learned anonymously from the complete observed cohort. They are benchmark-level calibration parameters, not corrections for a named model. An extension result at or below its cohort expectation contributes zero rather than a penalty.

Monotone Log-Sum-Exp Bonus and Dynamic Cap

For a model's positive observed residuals in one board, the raw bonus is:

raw_bonus = log(1 + sum(expm1(positive_residual_j)))

This form is zero-neutral and monotone: adding a zero residual changes nothing, while adding any positive residual cannot lower the bonus. It allows multiple independent frontier signals to corroborate one another.

One symmetric cap is recalculated from all pooled positive extension residuals in the current default cohort:

cap = mean(pooled_positive_residuals) + sqrt(2) × population_SD(pooled_positive_residuals)

bonus = min(cap, raw_bonus)

The cap is a data-derived cohort parameter and can change after a data refresh. It is not a hard-coded score for a provider or model. Capping limits repeated corroboration, but models with broader observed extension coverage still have more opportunities to produce a positive residual; extension counts are therefore published alongside scores.

Board and Final Score

board_score_b = min(100, core_score_b + bonus_b)

board_points_b = board_score_b / 5

AIndex = sum(board_points_b) = (1/5) × sum(board_score_b)

The displayed score, bar length, and rank all use this same quantity. Ranking uses the unrounded AIndex value; stable model ID is used only for an exact numerical tie. No model name, provider, family order, reserved position, mean rank, or post-hoc score calibration can move a row ahead of a higher calculated score.

Deduplication and Exact Configurations

The default leaderboard first selects one representative exact configuration for each variantGroup, then fits the anonymous extension trends and dynamic cap on that deduplicated cohort. This is also the calibration population used by the published ranking.

When Full Ranking shows every eligible tier, exact configurations use their own mandatory results. Only external evidence explicitly scoped to that exact variant with variantScoped may contribute to its extension bonus; family-level evidence is not concentrated onto one effort tier. The production export records the ranking grain and selected exact slug so the join can be audited.

Radar and Evidence Coverage

The first five radar axes read the five Scheme 18 board scores directly. The sixth axis is evidence coverage: it reports Core completeness and observed extension breadth but never changes a board score or rank.

Coverage is not a missing-data penalty. Core completeness is a scoring eligibility condition; after that condition is met, missing extension cells remain absent and the displayed score is based only on the Core plus observed positive residual evidence.

Sensitivity Views and Custom Tools

Equal-board 2PL, Core Rasch, Sparse Rasch, and Dense Rasch remain available as sensitivity views. They do not contribute a fixed percentage to Scheme 18 and cannot override its score order. Full Ranking may display standalone 2PL and Dense Rasch ranks for comparison only.

Custom tools can separately explore method ranks, capability-board weights, and per-benchmark calculations. These user-defined views do not reproduce or modify the default AIndex unless they implement the complete Scheme 18 Core, residual, cap, and five-board pipeline.

AIndex Calculation

  1. Load source-backed direct scores and canonical benchmark policy metadata.
  2. Select the default deduplicated population and require every board's mandatory Core.
  3. Calculate each Core as an unweighted geometric mean on the native 0–100 scale.
  4. Fit one anonymous non-negative-slope OLS trend per extension item and retain only observed positive residuals.
  5. Pool positive residuals to derive the dynamic mean + sqrt(2) × SD cap.
  6. Apply the monotone log-sum-exp bonus, cap it, and add it to the matching Core without imputing missing extension results.
  7. Average the five bounded board scores equally, sort the unrounded AIndex score descending, and publish Core, bonus, coverage, and sensitivity diagnostics.
Source: Artificial Analysis and linked independently controlled public benchmark sources. AInsights Index / AIndex recalculates Scheme 18 from observed results and publishes Core, extension, coverage, and sensitivity diagnostics alongside the score order.
